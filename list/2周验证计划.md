# 2 周验证计划

> **产品：** 午托伴侣 · 老师端 MVP  
> **目标：** 2 周内验证核心假设，并做 go / no-go 决策

---

## 一、验证什么

**核心假设（只验证这一条）：**

> 负责人认可，且老师（或负责人本人）能在午间独立完成「手拍播报」全流程，并感知到明显省时。

**暂不验证：** 无感监控、地推获客、家长端满意度。付费意愿在第 2 周通过口头问价或小范围早鸟收单试探（见商业判断）。

---

## 二、怎么验证

### 第 1 周 · 产品能否用起来

| 事项 | 动作 |
|------|------|
| 种子用户 | 母亲托管班深度试用；尽力再争取 **1–2 家** 外部机构 |
| 环境就绪 | H5 部署上线 + 1 页操作指引 |
| 核心场景 | 午餐「食安播报」启动试用，累计连续使用 **≥5 个工作日**，每天至少 1 次全流程 |
| 每日跟进 | 15 分钟微信回访：卡在哪步、文案要不要大改、省不省时间 |
| 产品迭代 | 只修阻断性 Bug 和 Prompt 问题，不加新功能 |

### 第 2 周 · 价值是否被感知

| 事项 | 动作 |
|------|------|
| 延续使用 | 种子用户保持每日使用，观察是否主动续用 |
| 价值确认 | 口头问价：「下学期继续用，你觉得值多少钱？」；对意愿明确者提供 **小范围早鸟收单**（¥199/学期），记录响应 |
| 对比沉淀 | 收集 1 组 Before / After |
| 复盘决策 | 输出 **1 页** 验证结论 |

---

## 三、成败标准

| 结果 | 条件 | 下一步 |
|------|------|--------|
| **通过** | **最低可行：** ≥1 家标杆机构深度验证通过（累计 ≥5 个工作日、核心播报流程 ≤15 分钟、负责人认可愿继续用）；**理想情况：** 再争取第 2 家复现 | 启动付费试探，扩至 5–10 家 |
| **待定** | 能用但耗时不降，或文案需大改 | 优化 Prompt 与流程，延长 1 周 |
| **不通过** | 中途放弃，或反馈「不如现在的方式」 | 复盘假设，调整场景或用户群 |

---

## 四、资源与风险

**人力：** 创始人全职跟进；研发按需修 Bug（3–5 人天）。  
**预算：** ¥300 以内（API + 部署），无地推。

| 风险 | 应对 |
|------|------|
| 午间太忙忘记用 | 约定试用时段，首日陪同走一遍 |
| 外部种子招不到 | 母亲托管班单点深度验证仍有效 |
| API 不稳定 | 重试 + 超时提示 |

---

## 五、2 周末交付

1. **验证结论**（1 页）：假设是否成立、用户原话、go / no-go  
2. **Before / After**（1 组）  
3. **Bug / 体验清单**

---

验证期原则：少写文档、多跟用户、少加功能、只拿证据。
